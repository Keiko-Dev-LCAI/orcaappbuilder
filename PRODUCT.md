# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Non-technical first-time builders on Lightchain AI who want to ship a simple app without writing code. They arrive from OrcaPod, hub listings, or word of mouth, often with a phone wallet and little developer experience. They need one clear next action per screen — not a dashboard of equal-weight options.

## Product Purpose

OrcaAppBuilder is an on-ramp: Learn → Brainstorm → Build → Launch Check → Troubleshoot, plus Links & Accounts. Success is a user who can describe an idea, get guided steps, and leave with something they can open or share — without needing a maintainer queue.

## Positioning

Calm, plain-English guidance for Lightchain builders. Sibling to other Orca apps (OrcaPod directory, OrcaGuard, OrcaVault, etc.). Free to use; optional tips support the project. Not a full IDE and not a paid unlock wall for core flows.

## Operating Context

Static web app (GitHub Pages / custom domain) with optional backend helpers. Wallet connect is available for tips and Lightchain context. Primary UI is a single `index.html` with section navigation (home modes + Learn / Brainstorm / Build / Launch / Troubleshoot / Links / Projects).

## Capabilities and Constraints

- Guided Learn lessons and Build / Brainstorm wizards in plain language.
- Launch Check scans for common shipping gaps (informational).
- Optional LCAI and KEIKO tip jars — tips only; do not gate core features.
- Must remain usable on mobile browsers; large touch targets matter.
- Do not invent hub listing guarantees, pricing, or partner endorsements.

## Brand Commitments

Voice: patient, direct, non-jargon-first. Explain crypto terms when they appear. Prefer one primary CTA per step. Keep the existing Orca dark + cyan family — polish within that system, do not rebrand.

## Evidence on Hand

- Live product copy and structure in `index.html`.
- Related notes: `ORCAAPPBUILDER-NOTES.md`, prior audit/fix task markdown in-repo (ops only).
- Tip address and pay helpers are present for optional support; core product stays free.

## Product Principles

1. **One clear action.** Every screen should make the next step obvious.
2. **Beginner-first language.** Hide code until the user asks to see it.
3. **Preserve trust.** No surprise paywalls; tips are optional and labeled.
4. **Stay in the Orca family.** Visual polish must still read as OrcaAppBuilder, not a generic AI template.

## Accessibility & Inclusion

Target WCAG 2.1 AA contrast for body text. Prefer readable type sizes (12px+ for UI chrome, 14–16px for body). Keyboard focus and large tap targets on primary controls. Respect that many users are on mobile wallets / small screens.
